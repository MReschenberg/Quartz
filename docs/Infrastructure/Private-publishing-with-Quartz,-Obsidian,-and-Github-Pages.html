Private publishing with Quartz, Obsidian, and Github Pages

Private publishing with Quartz, Obsidian, and Github Pages

Dec 11, 20256 min read

Outcome

This guide enables you to publish files from Obsidian to the web, without leaving Obsidian. At the end of it, you’ll be able to press one keyboard command and have your files visible at a URL.

Why do I want this?

The default building and publishing instructions for Quartz and Github Pages assume your markdown files are stored within a public Github repository. For those publishing from Obsidian, this may be undesirable — you may have both private and public files in your vault.

The following instructions describe how to publish with Quartz on Github Pages while maintaining your Obsidian vault in a separate, non-public location.

Note: These instructions require you use Obsidian on a machine that can build Quartz. This will not work, for example, from the Obsidian iOS app.

Let’s go!

This workflow hews as close as possible to the original Quartz/Github Pages instructions for maintainability. To start you should follow the Quartz instructions for cloning. You should also set up your own Github repo for your Quartz site.

The rest of these instructions assume your Obsidian content is located at $OBSIDIAN_PATH. This path should be absolute (not relative) and point to the root directory of your vault (this is the folder that contains the .obsidian directory). When this variable is mentioned, substitute it with your value.

If you store your vault in iCloud like me, make sure your path is correctly escaped for special characters like spaces (e.g. .../Mobile Documents/... should be .../Mobile\ Documents/...). The following instructions are intended for a Unix system.

Building, Serving, and Syncing Quartz

We’ll need to adjust the default build and serve commands we use for Quartz, as they rely on a few assumptions that we will break:

  • Quartz assumes content served for your site lives in the content directory
  • Quartz assumes you want your site’s static files written to a directory called public/

Luckily, Quartz is a fantastic piece of software and provides command line arguments for this work.

Building and Serving

To solve the first problem, we’ll use the --directory argument to pass our $OBSIDIAN_PATH. You should do this both when building (standalone) and serving (using --serve).

To solve the second problem, we’ll use the --o flag to change the name of our output directory. You should pass the string “docs” for this value, to support a Github Pages change we’ll make later.

Syncing

To synchronise your local Quartz directory with your Github repo, you should run npx quartz sync or npx quartz sync --no-pull per the Quartz documentation. No changes are necessary for this command.

Publishing to Github Pages

The Quartz instructions for Github Pages deployment involve configuring a Github Actions script to build and serve your content on a Github server.

We can forgo this and instead instruct Github to publish our already-generated static files directly. To enable this, open your Quartz repo on Github’s website.

  1. Navigate to your repo’s settings
  2. From the lefthand sidebar, select “Pages”
  3. Under “Build and Deployment > Source” select “Deploy from a branch”
  4. Select the main branch of your Quartz repo (mine is currently called “v4”)
  5. In the dropdown next to the branch, modify the selection from / (root) to /docs
  6. Hit “Save” to the right of the directory selector
  7. Wait a few minutes and refresh the page — you should see a banner declaring your site is live!

Your site should now be available for viewing at GithubUsername.github.io/QuartzRepositoryName

Use Obsidian’s Shell Command Plugin

Open your Obsidian settings and navigate to Community Plugins. If you haven’t disabled “Restricted Mode”, you’ll need to do that first.

Hit “Browse” and search for “Shell commands”. Install the plugin and enable it from the “Installed Plugins” list (you may need to restart Obsidian).

Hotkey Mapping

Because Obsidian is infinitely customisable, you are able to map this command to a hotkey combination. To do so, open Obsidian settings and navigate to “Hotkeys”. Then, search for “Shell command: Publish to Quartz”. Select it, press your desired key combination, and you’re all set!
